## Implementation deviations from v0.2 (each documented in the spec/architecture)
1. **Availability formula corrected** from `floor(start+duration)+1` to `ceil(start+duration)+1` minute: start times are truncated to the minute, so the v0.2 formula could expose a flow up to 1 minute before it truly ended. Unit-tested.
2. **No hyper-parameter grids:** calibration blocks hold 1–2 onsets, so tuning would fit noise; fixed values in config.
3. **Periodic baseline dropped:** tied scores make it fragile under quantile thresholds; the random-at-budget baseline already measures chance.
4. **Flat module layout** instead of sub-packages (simpler; same responsibilities).
5. **RF uses `n_jobs=1`:** multi-threaded summation gave last-bit differences between runs, which could flip an alarm at the threshold and break replay == evaluation.
6. **Added detection diagnostic** (`05b_detection_check.py`) to tell "no precursor" apart from "features blind to attacks". Not a headline result.
7. The Phase-3 power gate showed 3 (F1) and 5 (F2) training onsets — inside the range the spec anticipated — so, per your instruction not to stop unnecessarily, work continued and the limitation is reported prominently.

## Results log (copied from `results/REPORT.md`, config hash 74da90975d98)
- **RQ1/RQ2 — no reliable early warning.** Primary folds (10 test onsets), budget 1 FA/hour, static conformal: LogReg 1/10 warned, RF 1.0/10, XGBoost 1.2/10 (seed mean); random-alarm baseline 0.4/10; anomaly baseline 0/10. Detection intervals overlap fully (e.g. XGBoost 12% [0%, 32%] vs random 4% [0%, 10%]). The only warned onsets were the Friday DDoS (RF/XGB, all seeds, 3 min lead) and Thursday web brute-force (LogReg, 2 min lead); neither is warned under leave-one-day-out, so they do not replicate.
- **Window-level:** PR-AUC 0.11–0.18 vs positive rate 0.083 — slightly above chance, not enough for useful alarms.
- **RQ3 — alarm control works.** Realised false alarms/hour on primary test days 0.39–1.04 under a 1/hour budget. On Friday thresholds drift (quiet-minute exceedance 0.048–0.052 vs target 0.0167 for RF/XGB, static conformal); ACI lowered Friday false alarms from 1.11→0.67 (RF) and 1.48→0.74 (XGB) per hour.
- **RQ4 — drift/unseen families:** test families are unseen by construction; leave-one-day-out warned different onsets (FTP-Patator, SSH-Patator, slowloris partly) but model detection stays at 0–14% (the anomaly baseline reaches 21% with the fixed threshold), all overlapping the random baseline.
- **Sensitivity:** across G∈{5,10,15}, H∈{3,5,10}, model detection ranges 0–25% with intervals overlapping the random baseline (random rises to 10–15% at H=10, as expected for longer windows).
- **Day-identity control:** removing Monday from training changes little (XGBoost 14% vs 12%).
- **Detection diagnostic:** the same features detect running attacks with ROC-AUC 0.77–0.88 on Wed/Thu and 0.53–0.60 on Fri; 9 of the 12 campaigns on the F0–F2 test days are detected by ≥1 model after onset (missed: Heartbleed, PortScan 13:55, PortScan 14:14). ⇒ The features see attacks, but whole-network aggregates show little signal *before* onset.
